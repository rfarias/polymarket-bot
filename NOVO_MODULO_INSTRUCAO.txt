# NOVOS SETUPS — EV+ BASE RATE — Requisitos de Implementação
# Todos em PAPER ONLY na fase inicial

## CONTEXTO E FILOSOFIA

O bot já opera mercados de BTC 5min de forma quase ininterrupta.
Esses novos setups são complementares e operam com frequência muito menor
(horas a dias entre oportunidades), então podem rodar simultaneamente
sem conflito de recursos.

A estratégia central de todos os setups é a mesma:
  1. Calcular a probabilidade REAL do evento via fonte externa validada
  2. Comparar com o preço atual na Polymarket (= probabilidade implícita)
  3. Se diferença >= EDGE_MINIMUM: registrar entrada simulada (EV+)
  4. Aguardar resolução e registrar resultado

Não há previsão de direção, não há TA, não há momentum.
É pura comparação entre probabilidade real e preço de mercado.

## SETUP 1 — CLIMA / TEMPERATURA

Arquivo: ev_scanner/setups/weather.py
Ciclo: a cada 60 minutos

### Fonte de dados

Open-Meteo API (gratuita, sem chave, sem limite razoável de uso):
  Documentação: https://open-meteo.com/en/docs
  Endpoint histórico: https://archive-api.open-meteo.com/v1/archive
  Endpoint forecast: https://api.open-meteo.com/v1/forecast

  Parâmetros principais:
    latitude, longitude, daily, timezone, start_date, end_date

### Lógica de probabilidade real

Para cada mercado de temperatura ativo na Polymarket do tipo:
  "Highest temperature in [CITY] on [DATE]?"
  com buckets como: "<20°C", "20-22°C", "22-24°C", ">24°C"

  1. Buscar forecast do Open-Meteo para a cidade e data:
     temperature_2m_max (máxima diária prevista)
     temperature_2m_max com ensemble members (incerteza)

  2. Buscar histórico dos últimos 30 anos para a mesma data:
     calcular distribuição histórica de temperatura máxima

  3. Combinar forecast + histórico em probabilidade por bucket:
     peso_forecast = 0.70  (forecast é mais informativo perto da data)
     peso_historico = 0.30
     Se data > 7 dias: peso_forecast = 0.30, peso_historico = 0.70

  4. Probabilidade real por bucket = combinação ponderada

  Exemplo:
    Mercado: "Highest temperature in London on June 5?"
    Bucket: ">22°C"
    Forecast Open-Meteo: 68% de probabilidade
    Histórico 30 anos para 5 de junho em Londres: 52%
    Probabilidade combinada (< 7 dias): 0.70 × 68% + 0.30 × 52% = 63.2%
    Preço Polymarket: 50¢ (50%)
    Edge: 63.2% - 50% = 13.2% → ACIMA de 8% → ENTRAR

## SETUP 2 — FUTEBOL

Arquivo: ev_scanner/setups/soccer.py
Ciclo: a cada 120 minutos

### Fonte de dados

football-data.org (API gratuita com chave, tier free = 10 calls/min):
  Registro: https://www.football-data.org/client/register
  Variável no .env: FOOTBALL_DATA_API_KEY
  Endpoint resultados históricos:
    GET https://api.football-data.org/v4/competitions/{league}/matches
    Headers: {"X-Auth-Token": API_KEY}

  Ligas suportadas no tier gratuito:
    PL  (Premier League)
    PD  (La Liga)
    SA  (Serie A)
    BL1 (Bundesliga)
    FL1 (Ligue 1)
    CL  (Champions League)
    BSA (Brasileirão Série A)

FBref para xG (scraping, respeitar robots.txt):
  https://fbref.com/en/comps/ — dados de expected goals por jogo

### Lógica de probabilidade real

Para cada mercado de resultado de jogo na Polymarket:
  "Will [TEAM A] beat [TEAM B]?"
  "Match result: [TEAM A] vs [TEAM B]?"

  1. Buscar últimos 38 jogos de cada time via football-data.org:
     calcular win rate, draw rate, loss rate em casa e fora

  2. Calcular base rate histórica do confronto direto (H2H):
     últimos 10 confrontos diretos entre os dois times

  3. Se disponível, buscar xG dos últimos 10 jogos de cada time:
     xG_for (criação ofensiva) e xG_against (solidez defensiva)
     calcular probabilidade via modelo de Poisson simples

  4. Combinar os três fatores com pesos:
     prob_home_win = (
       0.40 × base_rate_home_form +
       0.30 × base_rate_h2h +
       0.30 × poisson_xg_model
     )

  Modelo de Poisson simplificado:
    lambda_home = media_xG_for_home × (media_xG_against_away / media_liga)
    lambda_away = media_xG_for_away × (media_xG_against_home / media_liga)
    P(home wins) = sum(P(X=i) × sum(P(Y=j) para j<i) para i em range(8))
    P(draw)      = sum(P(X=i) × P(Y=i) para i em range(8))
    P(away wins) = 1 - P(home wins) - P(draw)

  Médias da liga como referência: calcular dos últimos 380 jogos da liga

  5. Comparar com preço Polymarket e calcular edge

## SETUP 3 — FED RATE / MACRO

Arquivo: ev_scanner/setups/fed_rate.py
Ciclo: a cada 240 minutos (4 horas)

### Fonte de dados

CME FedWatch Tool (gratuito, público):
  Probabilidades implícitas de decisão do Fed via futuros de fed funds
  Endpoint público:
    https://www.cmegroup.com/markets/interest-rates/cme-fedwatch-tool.html
  Dados em JSON:
    https://www.cmegroup.com/CmeWS/mvc/Meeting/FedWatch/V2/
    (inspecionar requests da página para endpoint exato)

Alternativa mais estável — FRED API (Federal Reserve de St. Louis):
  Gratuita com chave: https://fred.stlouisfed.org/docs/api/fred/
  Variável no .env: FRED_API_KEY
  Série DFEDTARU: Fed Funds Target Rate Upper Bound
  Série DFEDTARL: Fed Funds Target Rate Lower Bound

  Histórico completo de decisões do Fed:
    Calcular base rate de: hold, hike+25, hike+50, cut-25, cut-50
    por contexto (inflação acima/abaixo de 2%, unemployment rate etc.)

### Lógica de probabilidade real

Para mercados do tipo:
  "Will the Fed cut rates at [meeting date]?"
  "Fed funds rate above X% by [date]?"

  1. Buscar probabilidade implícita do CME FedWatch para a reunião
  2. Calcular base rate histórica condicionada ao contexto atual:
     - Se CPI > 3.0%: Fed cortou em X% das reuniões historicamente
     - Se unemployment > 4.5%: Fed cortou em Y% das reuniões
  3. Combinar: 0.70 × CME_FedWatch + 0.30 × base_rate_contextual
  4. Comparar com preço Polymarket

Para mercados de CPI/PCE/inflação:
  Fonte: Cleveland Fed Inflation Nowcast (gratuito)
  URL: https://www.clevelandfed.org/indicators-and-data/inflation-nowcasting

nflreadr (dados públicos NFL):
  pip install nflreadr  (ou baixar CSVs em github.com/nflverse/nfldata)
  Histórico completo de jogos desde 1999

### Lógica de probabilidade real — NBA

Para mercados do tipo:
  "Will [TEAM A] beat [TEAM B]?" em jogo específico

  1. Buscar via nba_api os últimos 15 jogos de cada time:
     calcular win_rate_home e win_rate_away separadamente

  2. Calcular net_rating dos últimos 15 jogos:
     net_rating = points_for_avg - points_against_avg

  3. Modelo de probabilidade:
     net_diff = net_rating_home - net_rating_away
     home_advantage = 3.0  // pontos, constante histórica NBA
     prob_home = 1 / (1 + exp(-(net_diff + home_advantage) / 10))
     // logística calibrada nos dados históricos

  4. Ajuste por H2H últimas 3 temporadas:
     se h2h_win_rate disponível: peso 0.20 no resultado final

  5. Comparar com Polymarket e calcular edge

### Lógica de probabilidade real — NFL

Mesma lógica com ajustes:
  home_advantage = 2.5  // pontos, constante histórica NFL
  usar últimos 8 jogos (temporada mais curta)
  incluir: turnover differential, third down conversion rate

### Descoberta de mercados na Polymarket

Buscar na Gamma API por jogos das próximas 72 horas:

## UTILS COMPARTILHADOS

### polymarket_api.py

Funções para todos os setups usarem:

  get_active_markets(tag=None, limit=100) → list[dict]
    Busca mercados ativos na Gamma API com filtro de tag opcional

  get_market_price(market_slug) → dict
    Retorna preços atuais de YES/NO para um mercado

  get_market_volume(market_slug) → float
    Retorna volume total do mercado

  Endpoint base: https://gamma-api.polymarket.com/events

### ev_calculator.py

  calculate_edge(prob_real, price_market) → float
    edge = prob_real - price_market

  calculate_ev(prob_real, price_market, bet_size) → float
    ev = (prob_real × (1 - price_market) - (1 - prob_real) × price_market)
         × bet_size / price_market

  should_enter(edge, ev_per_dollar, min_edge=0.08) → bool
    return edge >= min_edge and ev_per_dollar > 0

  kelly_fraction(prob_real, price_market) → float
    b = (1 - price_market) / price_market  // odds decimais - 1
    kelly = (prob_real × b - (1 - prob_real)) / b
    return max(0, min(kelly, 0.25))  // cap em 25% do bankroll

### logger.py

  log_event(setup_name, event_dict) → None
    Escreve em logs/{setup_name}_paper_YYYYMMDD.jsonl
    E em logs/ev_scanner_decisions.jsonl (log consolidado)

## MÉTRICAS DE VALIDAÇÃO PARA MODO REAL

Após 50+ trades simulados RESOLVIDOS por setup:

  edge_realizado >= 0.06        // edge real após resolução
  win_rate >= prob_media_entrada × 0.90  // WR real >= 90% do esperado
  ev_por_trade >= $0.50
  sem viés sistematico de lado  // não estar errando sempre YES ou sempre NO

Se após 50 trades o edge_realizado for negativo:
  → revisar modelo de probabilidade, não aumentar edge_minimum
  → provável erro no modelo, não no conceito

## REGRAS INEGOCIÁVEIS

1. TODOS OS SETUPS INICIAM EM PAPER — nenhuma ordem real sem validação
2. EDGE MÍNIMO DE 8% — abaixo disso não entrar nem em paper
3. VOLUME MÍNIMO DE $500 no mercado — sem liquidez, sem entrada
4. NUNCA entrar em mercados sem fonte de resolução clara nas regras
5. CADA SETUP tem log separado — nunca misturar dados entre setups
6. O modelo de probabilidade deve ser documentado no log
   → nunca registrar só o resultado, sempre o raciocínio completo
7. Se a API externa estiver fora do ar: registrar "data_unavailable"
   no log e pular o ciclo — nunca usar última probabilidade conhecida
   como se fosse atual
