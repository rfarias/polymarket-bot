Quero construir um projeto chamado polymarket-resolution-edge-agent.

Objetivo:
Criar um agente/script para vasculhar mercados ativos da Polymarket, identificar a fonte de resolução de cada mercado, monitorar fontes públicas externas e detectar anomalias/assimetrias entre a odd justa estimada e o preço atual do book da Polymarket.

Importante:
O objetivo NÃO é usar informação privilegiada, hack, vazamento, scraping proibido ou qualquer fonte privada. O sistema deve usar apenas dados públicos, APIs públicas, páginas oficiais e fontes permitidas. A lógica é encontrar atraso, divergência ou má precificação entre dados públicos e o preço negociado na Polymarket.

Contexto:
Após vários testes de setups manuais e bots baseados em análise gráfica, book, BTC 5m/15m e reversões, os resultados práticos não foram positivos. A hipótese agora é que o edge real na Polymarket está em entender melhor a fonte de resolução de cada mercado e identificar situações em que o mercado ainda não precificou corretamente uma informação pública, objetiva e verificável.

Arquitetura desejada:

1. Market Scanner
- Buscar mercados ativos da Polymarket via Gamma API.
- Usar endpoint de eventos ativos, por exemplo:
  https://gamma-api.polymarket.com/events?active=true&closed=false&limit=100
- Implementar paginação por offset.
- Salvar para cada evento/mercado:
  - event_id
  - market_id
  - slug
  - title
  - description
  - resolution_rules / rules / umaResolutionStatus / qualquer campo relevante disponível
  - end_date
  - category / tags
  - volume
  - liquidity
  - outcomes
  - token_ids
  - best_bid
  - best_ask
  - spread
  - active/closed
  - accepting_orders

2. Resolution Source Classifier
- Ler título, descrição e regras de resolução.
- Classificar cada mercado em um tipo:
  - CHAINLINK_PRICE_FEED
  - EXCHANGE_PRICE
  - OFFICIAL_WEBSITE
  - SPORTS_SCORE_PROVIDER
  - WEATHER_DATA
  - ECONOMIC_RELEASE
  - SOCIAL_MEDIA_POST
  - NEWS_EVENT
  - MANUAL_AMBIGUOUS
  - UNKNOWN
- Extrair possíveis fontes citadas:
  - Chainlink
  - Binance
  - Coinbase
  - official website
  - X/Twitter
  - government site
  - sports API
  - weather API
  - economic calendar
  - outra fonte pública
- Quando a fonte não for identificável, marcar como UNKNOWN e não operar automaticamente.

3. Source Adapters
Criar uma arquitetura plugável de adapters.

Cada adapter deve implementar:
- canHandle(market)
- fetchCurrentState(market)
- estimateProbability(market, sourceState)
- getConfidence()
- getLatencyInfo()
- getResolutionRisk()

Adapters iniciais:

A) Chainlink BTC/USD adapter
- Ler preço atual do feed BTC/USD quando aplicável.
- Ler updatedAt/timestamp.
- Comparar Chainlink com Binance/Coinbase como fonte de preço atual de mercado.
- Detectar stale feed, diferença Chainlink vs exchanges e distância para o target do mercado.
- Calcular probabilidade justa de UP/DOWN considerando:
  - preço Chainlink atual
  - target do mercado
  - tempo restante
  - volatilidade recente
  - distância do target
  - direção e velocidade do preço
  - risco de atualização do Chainlink antes do fim

B) Exchange price adapter
- Usar Binance/Coinbase/Bybit públicos para preço spot.
- Calcular preço justo para mercados baseados em preço de exchange, se a regra de resolução permitir.

C) Official website adapter
- Monitorar páginas oficiais quando o mercado depender de uma publicação oficial.
- Detectar mudança de conteúdo, publicação de resultado ou anúncio.
- Nunca operar se a regra de resolução for ambígua.

4. Polymarket Order Book Monitor
- Buscar best bid/ask dos tokens YES/NO usando CLOB API.
- Manter stream em tempo real via WebSocket, se possível.
- Para cada mercado:
  - best_yes_bid
  - best_yes_ask
  - best_no_bid
  - best_no_ask
  - spread
  - liquidez no topo
  - profundidade até X ticks

5. Fair Value Engine
Para mercado binário:
- fair_yes = probabilidade estimada de YES vencer
- fair_no = 1 - fair_yes
- edge_buy_yes = fair_yes - best_yes_ask
- edge_buy_no = fair_no - best_no_ask
- edge_sell_yes = best_yes_bid - fair_yes
- edge_sell_no = best_no_bid - fair_no

Calcular edge líquido:
edge_liquido = edge_bruto - spread - slippage_estimado - custo - risco_resolucao - risco_fonte - risco_latencia

Somente gerar alerta se:
- edge_liquido >= threshold configurável
- confiança >= threshold
- liquidez mínima disponível
- fonte de resolução identificada
- risco de ambiguidade baixo ou aceitável
- tempo restante compatível com a estratégia

6. Risk Filter
Implementar filtros:
- Não operar mercados UNKNOWN.
- Não operar mercados com regra ambígua.
- Não operar mercados com risco alto de disputa UMA.
- Não operar se liquidez for baixa demais.
- Não operar se o spread consumir o edge.
- Não operar se a fonte externa estiver stale.
- Não operar se houver divergência entre fontes e não souber qual fonte resolve.
- Não usar all-in.
- Definir tamanho máximo por trade e por mercado.
- Definir stop lógico por invalidação da fonte/edge.
- Preferir modo alerta inicialmente, sem execução automática.
